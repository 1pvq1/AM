To build a resilient, multi-engine Markdown rendering system that allows you to hot-swap between a **mature production engine** and your **lenient "toy" fallback engine**, you need a structured, phased implementation plan.

Below is a comprehensive development blueprint tailored specifically for a Kotlin Multiplatform (KMP) chat application handling live LLM streaming.

---

### Phase 1: Architecture & Contract Definition (The Bridge)

Before writing any parsing logic, you must isolate your UI from the underlying markdown implementation. This ensures you can switch engines dynamically at runtime without changing a single line of Compose code.

#### 1. Define the Core Data Structures (`commonMain`)

Create a custom, shallow Abstract Syntax Tree (AST) representing chat-optimized formatting tokens:

```kotlin
sealed interface ChatNode {
    data class Text(val content: String, val isBold: Boolean = false, val isItalic: Boolean = false) : ChatNode
    data class Paragraph(val inlineNodes: List<Text>) : ChatNode
    data class Heading(val level: Int, val text: String) : ChatNode
    data class CodeBlock(val code: String, val language: String?, val isComplete: Boolean) : ChatNode
    data class ThinkBlock(val content: String, val isComplete: Boolean) : ChatNode // Specifically for DeepSeek/Thinking models
    data class UnsupportedRaw(val rawText: String) : ChatNode // Safe fallback
}

```

#### 2. Create the Strategy Interface

```kotlin
interface MarkdownEngine {
    val id: String
    fun parse(rawText: String, isStreaming: Boolean): List<ChatNode>
}

```

#### 3. Wire Up Koin for Hot-Swapping

Register a registry or a dynamic provider via Koin that tracks the user’s or developer's configuration:

```kotlin
class MarkdownEngineRegistry(
    private val matureEngine: MarkdownEngine,
    private val toyEngine: MarkdownEngine,
    private val settings: AppSettings // Your DataStore/SharedPreferences wrapper
) {
    fun getCurrentEngine(): MarkdownEngine {
        return if (settings.useMatureMarkdownEngine.value) matureEngine else toyEngine
    }
}

```

### Phase 2: Building the "Toy" Engine (Defensive & Custom)

The purpose of your toy engine is not to be a perfect Markdown spec-compliant parser, but to be **un-crashable** and **instantly patchable**.

#### 1. Implement Preprocessors

LLMs frequently break rules or invent tags. Write a chain of preprocessors to normalize strange outputs before parsing:

```kotlin
interface TextPreprocessor {
    fun process(input: String): String
}

// Example: Handles unfinished code blocks gracefully or converts raw web URLs into MD links
class StreamingSanitizer : TextPreprocessor {
    override fun process(input: String): String {
        // Fix weird trailing whitespace often generated by LLMs mid-stream
        return input.trimEnd { it == '\u200B' } 
    }
}

```

#### 2. Write the Shallow RegEx/Sequential Tokenizer

Instead of complex tree recursion, build a fast, linear line-by-line block processor:

* **Code Block Detection:** Scan for `````. If found, flip an `inCodeBlock` state flag. Everything until the next triple backtick belongs to a `CodeBlock` node.
* **Thinking Tag Detection:** Scan for `<think>` and `</think>`. If `<think>` is open but not closed, emit an incomplete `ThinkBlock`.
* **Inline Tokenizer:** For paragraphs, run a lightweight string tokenization for simple `bold` or `*italic*`.

---

### Phase 3: Integrating Mature Engines

Wrap a stable library inside your `MarkdownEngine` interface to handle complex formatting (tables, deeply nested bullet lists) when the LLM behaves perfectly.

#### Option A: KMP-Native Route (Recommended for Multiplatform Consistency)

Implement your `MatureEngine` wrapper around a library like **Multiplatform Markdown** or Atlassian's **Commonmark-Java** (which compiles fine in KMP common code). Map its heavy, deeply nested node classes into your simple, flat `ChatNode` primitives.

#### Option B: Platform-Specific Optimization (`expect/actual`)

If you require high-fidelity rendering, wrap **Markwon** on Android (`androidMain`) using an `AndroidView` wrapper, and use Apple's native **AttributedString Markdown parser** on iOS (`iosMain`).

### Phase 4: Constructing the UI "Cell Factory"

Now build the Compose Multiplatform UI components that draw these tokens inside your `FilesListPage` or chat bubbles.

```kotlin
@Composable
fun ChatMessageMarkdown(rawText: String, isStreaming: Boolean) {
    val registry: MarkdownEngineRegistry = koinInject()
    val currentEngine = registry.getCurrentEngine()
    
    // Remember the parsed nodes to avoid heavy re-computation on every minor frame redraw
    val nodes = remember(rawText, currentEngine) {
        currentEngine.parse(rawText, isStreaming)
    }

    Column(modifier = Modifier.fillMaxWidth()) {
        nodes.forEach { node ->
            ChatCellFactory(node = node)
        }
    }
}

@Composable
private fun ChatCellFactory(node: ChatNode) {
    when (node) {
        is ChatNode.Paragraph -> ParagraphCell(node)
        is ChatNode.Heading -> HeadingCell(node)
        is ChatNode.CodeBlock -> CodeBlockCell(node) // Renders with full syntax highlighting & copy button
        is ChatNode.ThinkBlock -> ThinkCollapseCell(node) // Renders inside a specialized expandable UI container
        is ChatNode.UnsupportedRaw -> Text(node.rawText)
    }
}

```

### Phase 5: Debugging, Telemetry, and Dynamic Switching

To maximize the value of this architecture, you must create tools to watch it work and react in real-time.

#### 1. The Developer "Hot-Fix" Panel

Build a hidden developer settings menu inside your app with:

* A toggle switch: `[ ] Use Mature Markdown Engine (Production)` vs `[X] Use Toy Engine (Fallback)`.
* An inspector overlay that badges chat bubbles with text indicating which engine rendered it (e.g., "[Toy]" or "[Mature]").

#### 2. Remote Configuration Integration

Hook the engine toggle configuration up to a remote configuration flag (like Firebase Remote Config or a simple JSON endpoint on your server).

* **The Scenario:** OpenAI or Anthropic releases a new model update tonight that changes how they formatting markdown outputs, and it breaks your mature library renderer.
* **The Response:** You toggle the remote configuration switch to instantly force all users to flip to your `SimpleToyParser`. Users get an un-broken app immediately. Meanwhile, you patch your toy parser's regex or wait for the mature open-source library to release an update.
